# גיבוי ושחזור

## מה מגובה ואיך
| שכבה | מה נשמר | תדירות | כמה זמן נשמר |
|---|---|---|---|
| **תמונות מצב של הדיסק (Fly)** | הכל: מסד הנתונים, תמונות, סרטונים, דפי נחיתה | פעם ביום, אוטומטית | 30 יום (`SNAPSHOT_RETENTION`) |
| **עותק יומי של מסד הנתונים** | משתמשים, שיחות, לידים, קמפיינים, נכסים | פעם ביום, בתוך המערכת | 7 עותקים אחרונים (`BACKUP_KEEP_DAYS`) |

העותקים היומיים נמצאים בשרת בתיקייה `/data/backups`, עם שמות כמו `agency-2026-11-06.db`. אחרי כל העלאה, בדוח של GitHub Actions מופיעה הערה בשם **backups** עם מספר תמונות המצב ורשימת העותקים.

## שחזור מסד הנתונים מעותק יומי (בלי שורת פקודה)
1. בגיטהאב נכנסים ל-**Actions**, ובוחרים **Deploy to Fly.io** ואז **Run workflow**.
2. בשדה **restore_db_copy** כותבים את שם העותק, למשל `agency-2026-11-05.db`.
3. לוחצים **Run workflow**.

לפני השחזור המצב הנוכחי נשמר בשם `before-restore-<תאריך>.db`, כך ששום דבר לא נמחק. אחרי השחזור המערכת עולה מחדש עם הנתונים מהעותק.

## שחזור הדיסק כולו מתמונת מצב
זה נדרש רק אם הדיסק עצמו אבד או נפגע. השחזור הזה דורש את כלי Fly (flyctl):
```
flyctl volumes snapshots list <volume-id> -a the-agency-power-kazabaroza
flyctl volumes create agency_data --snapshot-id <snapshot-id> -a the-agency-power-kazabaroza --region fra
```
אחרי זה מוחקים את הדיסק הישן ומריצים העלאה. אפשר לבקש מ-Claude לעשות את זה דרך GitHub Actions.

## שכבה נוספת (בהמשך)
אפשר להוסיף גם עותק אצל ספק אחסון חיצוני, כמו Cloudflare R2 או Backblaze. העותק הזה מגן גם אם החשבון ב-Fly עצמו נפגע. כדי להוסיף אותו צריך לפתוח חשבון אצל הספק ולשמור מפתח בגיטהאב.
